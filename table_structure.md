# 🗄️ Homaatri — Master Database Table Structure

This document outlines the complete 18-table relational database architecture for **Homaatri**, categorized by domain ownership and agent write permissions.

---

## 🔐 Domain Permission & Ownership Overview

| Domain | Table Prefix | Write Authority | Description |
| :--- | :--- | :--- | :--- |
| **Customer Domain** | `customer_*` | Customer Agent | Customer profiles, order headers, line items, payments, reviews, & WhatsApp transcripts. |
| **Chef Domain** | `chef_*` | Chef Agent | Home-cook profiles, menu catalogs, daily batch inventory, ready signals, & WhatsApp transcripts. |
| **Driver Domain** | `driver_*` | Driver Agent | Driver profiles, real-time GPS locations, trip statuses, & WhatsApp transcripts. |
| **Master / System Domain** | `system_*` | Master Agent | Cutoff meal windows, delivery routes, stop sequences, agent audit logs, & outbound WhatsApp queue. |

*Note: All 4 agents have **Global Read Access** to all 18 tables across all domains.*

---

## 📋 Table Inventory by Domain

### 1. Customer Domain (`customer_*`)
* **`customer_profiles`**: Customer account data, contact phone, delivery address, default latitude/longitude.
* **`customer_orders`**: Order headers (order_id, customer_id, meal_window [LUNCH/DINNER], pricing subtotal, delivery fee, total, order status).
* **`customer_order_items`**: Individual line items (menu_item_id, chef_id, quantity, unit_price, special instructions).
* **`customer_payments`**: Financial transaction logs, payment link URLs, payment status (PENDING, PAID, FAILED, TOPUP_PAID).
* **`customer_chat_history`**: WhatsApp conversation transcript log for Customer $\leftrightarrow$ Customer Agent turns.
* **`customer_reviews`**: Post-delivery rating & feedback for chefs and delivery drivers.

### 2. Chef Domain (`chef_*`)
* **`chef_profiles`**: Home-cook chef account data, kitchen name, address, kitchen latitude/longitude, active status.
* **`chef_menu_items`**: Master dish catalog (dish_name, description, unit price, meal_type [LUNCH/DINNER], active availability).
* **`chef_daily_inventory`**: Daily batch capacity management (date, max meal capacity, total units sold).
* **`chef_order_readiness`**: Meal prep & packing readiness signals (order_id, chef_id, status [PREPARING, PACKED_READY], packed_at timestamp).
* **`chef_chat_history`**: WhatsApp conversation transcript log for Chef $\leftrightarrow$ Chef Agent turns.

### 3. Driver Domain (`driver_*`)
* **`driver_profiles`**: Delivery driver account data, vehicle type, contact phone, active status.
* **`driver_locations`**: Real-time GPS location telemetry (driver_id, latitude, longitude, battery level, updated_at).
* **`driver_trip_status`**: Active delivery trip execution status (trip_id, driver_id, status [ASSIGNED, EN_ROUTE_PICKUP, AT_KITCHEN, EN_ROUTE_DELIVERY, DELIVERED]).
* **`driver_chat_history`**: WhatsApp conversation transcript log for Driver $\leftrightarrow$ Driver Agent turns.

### 4. Master / System Domain (`system_*`)
* **`system_meal_windows`**: Batch cutoff window manager (date, meal_type [LUNCH/DINNER], cutoff timestamp [12:00 PM / 7:00 PM], window status [OPEN, LOCKED_PROCESSING, COMPLETED]).
* **`system_delivery_routes`**: High-level delivery trip assignments generated by TSP solver linking Drivers to batch routes.
* **`system_delivery_stops`**: Sequential stop-by-stop itinerary (route_id, stop_number, stop_type [PICKUP_KITCHEN / DROPOFF_CUSTOMER], target_id, latitude, longitude, ETA, status).
* **`system_agent_logs`**: Audit trail for Master Agent relay calls and cross-domain write delegation requests.
* **`system_outbound_queue`**: Queue for outgoing WhatsApp notifications to be dispatched by the WhatsApp API gateway.
