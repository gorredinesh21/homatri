[SECTION 5: MULTI-AGENT ARCHITECTURE & DATA ACCESS SPECIFICATION]
--------------------------------------------------------------------------------

AGENT ROLES & TOPOLOGY:
1. Four Agents Total:
   - Master / Manager Agent (Central Supervisor / Orchestrator)
   - Customer Agent (Domain Specialist)
   - Chef Agent (Domain Specialist)
   - Delivery Driver Agent (Domain Specialist)

2. COMMUNICATION PATTERN (Hub-and-Spoke Mediator):
   - Subagents cannot communicate directly with each other.
   - All inter-role communications are relayed through the Master Agent.
   - Master Agent can talk directly to all three subagents.

3. DATABASE PERMISSION & WRITE ROUTING PROTOCOL:
   - READ ACCESS: Unrestricted across all 4 agents. All agents have global read-only access to all database tables (both same-domain and cross-domain).
   - WRITE ACCESS:
     * Subagents: Scoped strictly to their own domain tables (Customer Agent -> `customer_*`, Chef Agent -> `chef_*`, Driver Agent -> `driver_*`).
     * Master Agent: Global write access across all database tables.
   - CROSS-DOMAIN WRITE ROUTING:
     * If a Subagent requests a cross-domain write, it asks the Master Agent -> Master Agent delegates/sends the write request to the target domain Subagent -> Target Subagent performs the write in its own domain.
     * If a write is initiated by the Master Agent itself (e.g. system cutoffs, system orchestration), the Master Agent executes the write directly using its own global write access.

   - Authored comprehensive specification file `ai agent architecture.md` detailing topology, read/write matrices, delegation flows, and operational lifecycles.

[SECTION 7: LANGGRAPH HUMAN-IN-THE-LOOP (HITL) & AGENT RELAY PATTERN]
--------------------------------------------------------------------------------

KEY INSIGHT & ARCHITECTURAL BREAKTHROUGH:
1. RAW TRANSCRIPT PASSING ANTIPATTERN REJECTED:
   - Passing raw chat history (e.g. last 10 messages) creates massive token bloat, causes context loss when window shifts, and pollutes specialist prompt contexts with unrelated dialogue.

2. STRUCTURED INTENT RELAY & HITL FLOW:
   - Subagents extract clean JSON intent payloads (e.g. `{"order_id": "ord_104", "request": "No garlic"}`).
   - Relay Chain: Customer Agent -> Master Agent -> Target Subagent (Chef/Driver Agent).
   - LangGraph `interrupt()`: Target Subagent triggers `interrupt()`, saving checkpoint state to DB and pausing execution.
   - WhatsApp Notification: Human actor (Chef/Driver/Admin) receives WhatsApp notification.
   - Resume Execution: Human reply triggers webhook, loading DB checkpoint and resuming graph execution to confirm back up the chain.


3. DOCUMENTATION:
   - Authored `langgraph_hitl_relay.md` specifying the complete HITL relay architecture, sequence diagrams, and use cases.
