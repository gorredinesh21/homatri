# 🚴‍♂️ Master Specification: The Delivery Driver Agent

This document outlines the complete persona, communication rules, categories, toolset, and guardrails for the **Delivery Driver Agent** in Homaatri.

---

## 🎭 1. Persona & Communication Rules
* **Human Persona**: Fast-paced, concise, practical, and location-aware. Speaks in clear, short WhatsApp updates for delivery drivers on the road.
* **Core Rule**: Admin handles driver onboarding in DB. Deliveries are made to Apartment Security Gates (no doorstep flat delivery). Uses GCP Route Optimization API for single-leg navigation (`Stop N ➔ Stop N+1`).

---

## 🛠️ 2. Driver Agent Action & Toolset (9 Actions)

### 📍 CATEGORY 1: Driver Profile Lookup

#### 1. `get_driver_profile(phone_number)`
* **Purpose**: Identifies an onboarded delivery driver on incoming WhatsApp webhook.
* **Inputs**: `phone_number: str` (E.164 format)
* **Outputs**: `dict | None` (Driver profile details or `None` if unauthorized).
* **DB Operation**: `SELECT * FROM driver_profiles WHERE phone_number = ?` (Read)

---

### 📡 CATEGORY 2: Real-Time GPS Location Telemetry

#### 2. `update_driver_location(driver_id, latitude, longitude, battery_level)`
* **Purpose**: Logs real-time GPS coordinates and phone battery status from driver's device background ping.
* **Inputs**: `driver_id: str`, `latitude: float`, `longitude: float`, `battery_level: int | None`
* **Outputs**: `dict` (Telemetry logged confirmation).
* **DB Operation**: `INSERT INTO driver_locations ...` (Write - `driver_locations`)

---

### 🗺️ CATEGORY 3: Sequential Leg Navigation

#### 3. `get_assigned_route_itinerary(driver_id, meal_window, date)`
* **Purpose**: Fetches the master sequenced stop list (`Stop 1 ➔ Stop 2 ➔ ... ➔ Stop N`) generated by GCP Route Optimization API at cutoff.
* **Inputs**: `driver_id: str`, `meal_window: str`, `date: str`
* **Outputs**: `dict` (Master stop sequence, total stops, apartment gate consolidated stop count).
* **DB Operation**: Global Read on `system_delivery_routes` & `system_delivery_stops`. (Read)

#### 4. `dispatch_next_leg_navigation_link(driver_id, current_stop_index)`
* **Purpose**: Generates a single Google Maps navigation link from the driver's **current stop location to the VERY NEXT stop location (`Stop N ➔ Stop N+1`)**.
* **Inputs**: `driver_id: str`, `current_stop_index: int`
* **Outputs**: `dict` (Next stop details, order IDs to deliver/pickup, single-leg Google Maps URL).
* **DB Operation**: Global Read on `system_delivery_stops`. (Read)

---

### 🏁 CATEGORY 4: Stop Execution & Delivery Handshakes

#### 5. `mark_driver_reached_stop(driver_id, stop_id)`
* **Purpose**: Triggered when driver messages *"Reached"* or taps button at a kitchen or gate stop.
* **Inputs**: `driver_id: str`, `stop_id: str`
* **Outputs**: `dict` (Stop status updated to `ARRIVED`).
* **DB Operation**: `UPDATE system_delivery_stops SET status = 'ARRIVED' ...` & `UPDATE driver_trip_status ...` (Write - `driver_*`)

#### 6. `mark_orders_picked_up(driver_id, stop_id, order_ids_list)`
* **Purpose**: Triggered when driver picks up packed meals from a kitchen. Automatically triggers `dispatch_next_leg_navigation_link`.
* **Inputs**: `driver_id: str`, `stop_id: str`, `order_ids_list: list[str]`
* **Outputs**: `dict` (Orders marked `PICKED_UP`, next leg navigation link).
* **DB Operation**: `UPDATE customer_orders SET status = 'PICKED_UP' ...` & `UPDATE driver_trip_status ...` (Write - `driver_*`)

#### 7. `mark_gate_delivery_completed(driver_id, stop_id, order_ids_list, left_with_security)`
* **Purpose**: Triggered when driver completes gate drop-off for multiple apartment orders (*"Delivered 5 orders to My Home Bhooja Security Guard"*).
* **Inputs**: `driver_id: str`, `stop_id: str`, `order_ids_list: list[str]`, `left_with_security: bool`
* **Outputs**: `dict` (Orders marked `DELIVERED`, notifies Customer Agent $\rightarrow$ Customers on WhatsApp).
* **DB Operation**: `UPDATE customer_orders SET status = 'DELIVERED'` & `UPDATE system_delivery_stops ...` (Write - `driver_*`)

---

### 🤝 CATEGORY 5: HITL & Exception Management

#### 8. `report_unlocatable_address_hitl(driver_id, stop_id, order_id)`
* **Purpose**: Triggered when driver reports *"Address not found"*. Calls LangGraph `interrupt()`, alerting Master Agent $\rightarrow$ Customer Agent to prompt the customer on WhatsApp to send a location pin update.
* **Inputs**: `driver_id: str`, `stop_id: str`, `order_id: str`
* **Outputs**: `dict` (Execution paused; waiting for customer location pin update).
* **DB Operation**: Saves checkpoint to LangGraph state checkpointer.

#### 9. `report_vehicle_delay_alert(driver_id, delay_minutes, reason)`
* **Purpose**: Triggered when driver reports traffic or breakdown. Updates ETAs and notifies Master Agent to alert affected customers.
* **Inputs**: `driver_id: str`, `delay_minutes: int`, `reason: str`
* **Outputs**: `dict` (Updated ETAs across delivery stops).
* **DB Operation**: `UPDATE system_delivery_stops SET estimated_arrival = ...` (Write - `driver_*`)
